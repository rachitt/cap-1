## Description

Every later layer imports its vocabulary from Layer 1. This story establishes the Pydantic models, string enums and typed exception classes for customers, KYC, accounts, transactions, transfers, beneficiaries, loans, audit entries and notifications. The types package imports nothing from any other layer, which is the base case for the NFR-08 architecture tests.

## Acceptance Criteria

**AC1.** The `backend/src/types/` package defines string enums `Role` (CUSTOMER, ADMIN), `CustomerStatus` (PENDING_KYC, ACTIVE, SUSPENDED), `KycStatus` (PENDING, VERIFIED, REJECTED), `AccountStatus` (ACTIVE, CLOSED), `TransactionDirection` (DEBIT, CREDIT), `TransferStatus` (COMPLETED, FAILED), `LoanStatus` (APPLIED, UNDER_REVIEW, APPROVED, REJECTED, DISBURSED) and `NotificationStatus` (QUEUED, SENT, FAILED).

| Feature | Category | Verifies |
|---|---|---|
| `F001` | functional | All eight domain enums expose exactly the member names specified in the BRD data model |

**AC2.** A typed exception hierarchy rooted at `DomainError` provides `MoneyPrecisionError`, `InsufficientFundsException`, `SelfTransferError`, `InactiveAccountError`, `IllegalLoanTransitionError`, `KycAlreadySubmittedError` and `OwnershipError`, each carrying a machine-readable `error_code` string attribute. Every error traces to a stated rule; no error exists for a withdrawn rule such as a transfer cap or a beneficiary precondition.

| Feature | Category | Verifies |
|---|---|---|
| `F002` | functional | Every domain exception subclasses DomainError and exposes a distinct non-empty error_code |
| `F003` | integration | No exception type exists for a withdrawn rule such as a transfer cap or beneficiary precondition |

**AC3.** The `types` package imports nothing from `config`, `domain`, `repository`, `service` or `api`; a grep over `backend/src/types/` for those module names returns zero matches.

| Feature | Category | Verifies |
|---|---|---|
| `F004` | integration | The types package has zero outbound imports to any higher layer |

**AC4.** Every public class and function in `backend/src/types/` carries complete type annotations; `uv run mypy --strict src/types/` reports zero errors.

| Feature | Category | Verifies |
|---|---|---|
| `F005` | functional | The types package passes mypy in strict mode with zero errors |

## Verification Steps

**`F001` — All eight domain enums expose exactly the member names specified in the BRD data model** _(AC1, functional)_

1. Import Role, CustomerStatus, KycStatus, AccountStatus, TransactionDirection, TransferStatus, LoanStatus and NotificationStatus from backend.src.types
1. Assert set(Role) member values equal {'CUSTOMER','ADMIN'}
1. Assert set(LoanStatus) member values equal {'APPLIED','UNDER_REVIEW','APPROVED','REJECTED','DISBURSED'}
1. Assert every enum member is a str subclass so it serialises to JSON as its value

**`F002` — Every domain exception subclasses DomainError and exposes a distinct non-empty error_code** _(AC2, functional)_

1. Import DomainError and its seven named subclasses from backend.src.types
1. Assert each subclass is a subclass of DomainError
1. Assert InsufficientFundsException().error_code == 'INSUFFICIENT_FUNDS'
1. Assert the set of error_code values across all subclasses has no duplicates and none is empty

**`F003` — No exception type exists for a withdrawn rule such as a transfer cap or beneficiary precondition** _(AC2, integration)_

1. Run: grep -rniE 'DailyTransferCap|CapExceeded|NotBeneficiary|Eligibility.*Error' backend/src/types/
1. Assert the command exits with status 1 (no matches)
1. Enumerate all DomainError subclasses and assert none relates to a transfer cap, velocity limit or beneficiary requirement

**`F004` — The types package has zero outbound imports to any higher layer** _(AC3, integration)_

1. Run: grep -rnE 'from (backend\.)?src\.(config|repository|service|api)|import (backend\.)?src\.(config|repository|service|api)' backend/src/types/
1. Assert the command exits with status 1 (no matches found)
1. Import backend.src.types in a fresh interpreter and assert no ImportError is raised

**`F005` — The types package passes mypy in strict mode with zero errors** _(AC4, functional)_

1. Run: cd backend && uv run mypy --strict src/types/
1. Assert the process exit code is 0
1. Assert stdout contains 'Success' and does not contain 'error:'
