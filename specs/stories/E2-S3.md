## Description

Orchestrates AC-01. Registration hashes the password with a modern KDF and creates a PENDING_KYC customer. KYC submission runs the pure policy, records the verdict, and flips the customer to ACTIVE on a VERIFIED result. Login issues a 30-minute JWT only for ACTIVE customers, so a pre-KYC login is distinguishable from a bad password.

## Acceptance Criteria

**AC1.** `register` stores a password hash produced by a modern KDF (bcrypt or argon2), never the plaintext; the stored hash does not equal the input password and verifies against it.

| Feature | Category | Verifies |
|---|---|---|
| `F043` | security | Registration stores a KDF hash rather than the plaintext password |
| `F044` | security | Registering an email that already exists raises a duplicate error and creates no second customer |

**AC2.** `submit_kyc` on a well-formed document sets the KYC record to VERIFIED and transitions the customer from `PENDING_KYC` to `ACTIVE`; a reserved-number document leaves the customer at `PENDING_KYC` with a REJECTED record.

| Feature | Category | Verifies |
|---|---|---|
| `F045` | functional | A passing KYC submission activates the customer account |
| `F046` | functional | A rejected KYC submission leaves the customer inactive |

**AC3.** Submitting KYC a second time for a customer that already has a VERIFIED record raises `KycAlreadySubmittedError` (edge case E-10) and does not create a second KYC row.

| Feature | Category | Verifies |
|---|---|---|
| `F047` | functional | A duplicate KYC submission raises KycAlreadySubmittedError and creates no second record |

**AC4.** `login` returns a signed JWT whose payload carries `sub` (customer id), `role` and an `exp` 30 minutes in the future for an ACTIVE customer with correct credentials.

| Feature | Category | Verifies |
|---|---|---|
| `F048` | functional | Successful login issues a JWT carrying subject, role and a 30-minute expiry |

**AC5.** `login` raises an authentication error for a wrong password and a distinct not-activated error for a customer still in `PENDING_KYC`, so the API can return 401 and 403 respectively (edge case E-09).

| Feature | Category | Verifies |
|---|---|---|
| `F049` | security | A wrong password raises an authentication error distinct from the not-activated error |
| `F050` | security | Login by a PENDING_KYC customer raises a distinct not-activated error |

## Verification Steps

**`F043` — Registration stores a KDF hash rather than the plaintext password** _(AC1, security)_

1. Call register with password 'Hunter2!Secure'
1. Read the persisted customer row
1. Assert password_hash != 'Hunter2!Secure' and len(password_hash) > 40
1. Assert the hash prefix identifies bcrypt or argon2 and that verifying 'Hunter2!Secure' against it returns True

**`F044` — Registering an email that already exists raises a duplicate error and creates no second customer** _(AC1, security)_

1. Call register with email 'dup@horizon.test'
1. Call register again with the same email inside pytest.raises for the duplicate-email error
1. Assert the error is raised
1. Assert exactly one customer row exists for that email

**`F045` — A passing KYC submission activates the customer account** _(AC2, functional)_

1. Register a customer and assert status is PENDING_KYC
1. Call submit_kyc with document_type='PASSPORT' and document_number='P1234567'
1. Re-read the customer and assert status == CustomerStatus.ACTIVE
1. Assert the linked KYC record status is VERIFIED

**`F046` — A rejected KYC submission leaves the customer inactive** _(AC2, functional)_

1. Register a customer and call submit_kyc with document_number='X0000000'
1. Assert the KYC record status is REJECTED
1. Re-read the customer and assert status is still CustomerStatus.PENDING_KYC

**`F047` — A duplicate KYC submission raises KycAlreadySubmittedError and creates no second record** _(AC3, functional)_

1. Register a customer and complete a successful KYC submission
1. Call submit_kyc again for the same customer inside pytest.raises(KycAlreadySubmittedError)
1. Assert the error is raised
1. Count kyc_records rows for that customer_id and assert the count is 1

**`F048` — Successful login issues a JWT carrying subject, role and a 30-minute expiry** _(AC4, functional)_

1. Register and activate a customer, then call login with the correct password
1. Decode the returned token with the configured signing key
1. Assert the payload 'sub' matches the customer id and 'role' equals 'CUSTOMER'
1. Assert exp minus iat equals 1800 seconds

**`F049` — A wrong password raises an authentication error distinct from the not-activated error** _(AC5, security)_

1. Register and activate a customer
1. Call login with an incorrect password inside pytest.raises for the authentication error
1. Assert the raised error type is the invalid-credentials error, not the not-activated error
1. Assert no token is returned

**`F050` — Login by a PENDING_KYC customer raises a distinct not-activated error** _(AC5, security)_

1. Register a customer without submitting KYC
1. Call login with the correct password inside pytest.raises for the not-activated error
1. Assert the raised error is distinguishable from the invalid-credentials error by its error_code
1. Assert no token is returned
