## Description

The graded submission target is GitLab, so `.gitlab-ci.yml` is the CI artefact, not a GitHub workflow. The pipeline runs build and test stages for both workspaces, enforces the 80% coverage floor as a blocking gate, runs the architecture structural tests, and wires in the Claude Code Action per brief section 7.1.

## Acceptance Criteria

**AC1.** `.gitlab-ci.yml` exists at the repository root, parses as valid YAML, and defines at least a build stage and a test stage covering both the backend and the frontend (M-12).

| Feature | Category | Verifies |
|---|---|---|
| `F240` | integration | The GitLab CI configuration is valid and defines build and test stages for both workspaces |
| `F241` | integration | No GitHub Actions workflow is used as the graded CI artefact |

**AC2.** The pipeline fails when coverage falls below the 80% floor: a run with coverage under the threshold exits non-zero, and the coverage artefact is committed (M-05).

| Feature | Category | Verifies |
|---|---|---|
| `F242` | integration | The coverage gate blocks the pipeline below the 80% floor |

**AC3.** The Claude Code Action is wired into the pipeline as a job, referencing its credentials from CI variables rather than committed secrets (brief section 7.1).

| Feature | Category | Verifies |
|---|---|---|
| `F243` | security | The Claude Code Action job reads credentials from CI variables and commits no secret |

**AC4.** The pipeline runs the lint and typecheck gates for both workspaces, failing on any ruff, mypy, eslint or tsc error.

| Feature | Category | Verifies |
|---|---|---|
| `F244` | integration | Lint and typecheck gates run for both workspaces and fail the pipeline on error |

## Verification Steps

**`F240` — The GitLab CI configuration is valid and defines build and test stages for both workspaces** _(AC1, integration)_

1. Assert .gitlab-ci.yml exists at the repository root
1. Parse the file with a YAML parser and assert it loads without error
1. Assert the stages list includes a build stage and a test stage
1. Assert jobs exist that run the backend pytest suite and the frontend vitest suite

**`F241` — No GitHub Actions workflow is used as the graded CI artefact** _(AC1, integration)_

1. Assert .gitlab-ci.yml is present and non-empty
1. Assert the CI test job references the architecture structural tests
1. Assert the pipeline does not depend on .github/workflows to run the graded checks

**`F242` — The coverage gate blocks the pipeline below the 80% floor** _(AC2, integration)_

1. Run the backend test job with the coverage threshold configured at 80
1. Assert pytest is invoked with a fail-under setting of 80
1. Simulate a run whose coverage is below 80 and assert the job exits non-zero
1. Assert the committed coverage artefact exists after a passing run

**`F243` — The Claude Code Action job reads credentials from CI variables and commits no secret** _(AC3, security)_

1. Assert .gitlab-ci.yml defines a job invoking the Claude Code Action or equivalent
1. Assert the job references an API key through a CI variable reference
1. Run: grep -nE 'sk-ant|ANTHROPIC_API_KEY\s*[:=]\s*[A-Za-z0-9]' .gitlab-ci.yml
1. Assert the command returns no match

**`F244` — Lint and typecheck gates run for both workspaces and fail the pipeline on error** _(AC4, integration)_

1. Assert the pipeline defines jobs running ruff check and mypy for the backend
1. Assert it defines jobs running eslint and tsc for the frontend
1. Introduce a deliberate type error and run the typecheck job
1. Assert the job exits non-zero, then revert and assert it passes
