## Description

Mandatory deliverable: a single command brings the whole system up from a clean checkout. Seed data must let the evaluator and the Playwright suite exercise every AC without manual setup, which per assumption A-12 means funded customers, a saved beneficiary, loans in each reviewable state and exactly one seeded administrator. All data is synthetic per DR-36.

## Acceptance Criteria

**AC1.** `./init.sh` from a clean checkout installs dependencies, runs migrations, seeds the database and starts both services, after which `/health` returns 200 and the UI root responds (M-15).

## Verification Steps

**`F234` — init.sh brings the full stack up from a clean checkout** _(AC1, integration)_

1. From a clean checkout with no database file, run ./init.sh
1. Poll http://localhost:8000/health with 5 retries at 2s backoff
1. Assert a 200 response with status 'ok' is received
1. Assert the frontend root at http://localhost:3000 returns a 200 response

**`F235` — The seed script is idempotent and can be re-run without duplicating data** _(AC1, integration)_

1. Run the seed script twice against the same database
1. Assert the second run exits with status 0
1. Assert the customer count is the same after both runs
1. Assert exactly one admin customer exists

**`F236` — Seeded data covers funded customers, a beneficiary and loans in each reviewable state** _(AC2, integration)_

1. Run the seed script against a clean database
1. Assert at least 2 customers exist with role CUSTOMER and at least one account each with a balance above 0.00
1. Assert at least one beneficiary row exists
1. Assert at least one loan exists in each of APPLIED, UNDER_REVIEW and APPROVED status

**`F237` — Exactly one administrator exists and is created only by the seed script** _(AC2, security)_

1. Run the seed script and query customers with role ADMIN
1. Assert exactly one admin row exists
1. Run: grep -rn 'Role.ADMIN' backend/src/api/ and assert no route assigns the ADMIN role

**`F238` — All seeded records use reserved synthetic identifiers** _(AC3, security)_

1. Read every seeded customer email address
1. Assert each uses a reserved test domain such as .test or example.com
1. Assert no seeded document number matches a real-world identifier format in production use
1. Run the detect-secrets hook against the seed script and assert it reports no findings

**`F239` — The README quick-start covers prerequisites, the run command and seeded credentials** _(AC4, integration)_

1. Assert README.md exists and contains a quick-start section
1. Assert it names the prerequisite runtimes and the ./init.sh command
1. Assert it documents the seeded administrator login and the API and UI URLs
1. Assert it states that all data is synthetic
