## Description

Three NFRs land together because they share one middleware stack. NFR-07 requires /health to answer 200 within a second of startup, NFR-06 requires structured JSON logs carrying a request correlation ID, and NFR-03 requires that passwords, tokens and document numbers never reach a log line. The redaction filter is applied at the logging handler so no caller can bypass it.

## Acceptance Criteria

**AC1.** `GET /health` returns HTTP 200 with a JSON body containing `status: "ok"` and performs a trivial database round-trip, responding within 1 second of successful startup (NFR-07).

| Feature | Category | Verifies |
|---|---|---|
| `F025` | functional | GET /health returns 200 with status ok and completes within one second |
| `F026` | integration | The health check exercises a real database round-trip rather than returning a static literal |

**AC2.** Every request emits at least one log line that is valid JSON and contains the keys `timestamp`, `level`, `message` and `correlation_id` (NFR-06).

| Feature | Category | Verifies |
|---|---|---|
| `F027` | functional | Each request produces a parseable JSON log line carrying the four required keys |

**AC3.** A caller-supplied `X-Correlation-ID` request header is echoed in the response header and appears as the `correlation_id` in that request's log lines; when absent, the middleware generates a UUID and requests receive distinct IDs.

| Feature | Category | Verifies |
|---|---|---|
| `F028` | functional | A supplied X-Correlation-ID propagates into both the response header and the log records |
| `F029` | functional | Absent a supplied header the middleware generates a distinct correlation ID per request |

**AC4.** The redaction filter removes passwords, bearer tokens and KYC document numbers from log output: logging a payload containing `"password": "Hunter2!"` and a document number emits `***REDACTED***` in their place and the raw values appear nowhere in stdout (NFR-03).

| Feature | Category | Verifies |
|---|---|---|
| `F030` | security | Passwords and bearer tokens are replaced with a redaction marker in emitted logs |
| `F031` | security | KYC document numbers are redacted from log output |

## Verification Steps

**`F025` — GET /health returns 200 with status ok and completes within one second** _(AC1, functional)_

1. Start the backend and wait for the startup event to complete
1. Record a monotonic timestamp, then issue GET /health
1. Assert the response status is 200 and the JSON body field 'status' equals 'ok'
1. Assert the elapsed wall-clock time for the request is under 1.0 second

**`F026` — The health check exercises a real database round-trip rather than returning a static literal** _(AC1, integration)_

1. Point the application at an unreachable or corrupt database URL
1. Issue GET /health
1. Assert the response status is not 200, proving the handler actually queries the database

**`F027` — Each request produces a parseable JSON log line carrying the four required keys** _(AC2, functional)_

1. Capture stdout while issuing GET /health
1. Parse each emitted line with json.loads and assert no line fails to parse
1. Assert at least one parsed record contains the keys timestamp, level, message and correlation_id
1. Assert the correlation_id value is a non-empty string

**`F028` — A supplied X-Correlation-ID propagates into both the response header and the log records** _(AC3, functional)_

1. Issue GET /health with header X-Correlation-ID: test-corr-123
1. Assert the response header X-Correlation-ID equals 'test-corr-123'
1. Assert at least one captured JSON log record has correlation_id == 'test-corr-123'

**`F029` — Absent a supplied header the middleware generates a distinct correlation ID per request** _(AC3, functional)_

1. Issue two sequential GET /health requests with no X-Correlation-ID header
1. Collect the correlation_id from each response header
1. Assert both values are non-empty and parse as UUIDs
1. Assert the two values are not equal

**`F030` — Passwords and bearer tokens are replaced with a redaction marker in emitted logs** _(AC4, security)_

1. Log a structured record containing password='Hunter2!' and authorization='Bearer abc.def.ghi'
1. Capture the emitted log output as a string
1. Assert 'Hunter2!' does not appear anywhere in the output
1. Assert 'abc.def.ghi' does not appear and '***REDACTED***' does appear

**`F031` — KYC document numbers are redacted from log output** _(AC4, security)_

1. POST /api/v1/auth/register then submit a KYC payload with document_number='X1234567'
1. Capture all log output produced during the request
1. Assert 'X1234567' does not appear in any emitted log line
