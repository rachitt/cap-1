## Description

NFR-08 in executable form. At least three structural tests assert the one-way dependency rule, using import-linter for the Python backend and dependency-cruiser for the frontend. These fail the build on a violation rather than relying on the write-time hook alone, so drift cannot survive a merge.

## Acceptance Criteria

**AC1.** At least three structural tests exist under `tests/architecture/` and all pass; the suite is executed by the default test command rather than requiring a separate invocation (NFR-08, M-09).

| Feature | Category | Verifies |
|---|---|---|
| `F222` | integration | At least three architecture structural tests exist and pass in the default test run |

**AC2.** An import-linter contract encodes the layer order Types → Config → Repository → Service → API and fails when a lower layer imports a higher one; a deliberately introduced violation makes the check exit non-zero.

| Feature | Category | Verifies |
|---|---|---|
| `F223` | integration | The import-linter contract passes against the clean codebase |
| `F224` | integration | An injected upward import is detected and fails the contract |

**AC3.** A structural test asserts that no API route handler imports a repository module directly, enforcing the rule that controllers never call repositories.

| Feature | Category | Verifies |
|---|---|---|
| `F225` | integration | No API route module imports a repository module directly |

**AC4.** A structural test asserts that `backend/src/domain/` imports nothing outside the standard library and `src/types`, keeping the domain policies a dependency-free Layer-1 sibling of types.

| Feature | Category | Verifies |
|---|---|---|
| `F226` | integration | The domain policy package has no dependency outside the standard library and types |

**AC5.** A dependency-cruiser configuration enforces the frontend module boundaries and reports zero violations on the clean codebase.

| Feature | Category | Verifies |
|---|---|---|
| `F227` | integration | Dependency-cruiser reports zero frontend boundary violations |

## Verification Steps

**`F222` — At least three architecture structural tests exist and pass in the default test run** _(AC1, integration)_

1. Count test functions under tests/architecture/ and assert the count is at least 3
1. Run the default backend test command
1. Assert the architecture tests are collected and all pass
1. Assert the process exit code is 0

**`F223` — The import-linter contract passes against the clean codebase** _(AC2, integration)_

1. Run: cd backend && uv run lint-imports
1. Assert the process exit code is 0
1. Assert the output reports the layered contract as kept

**`F224` — An injected upward import is detected and fails the contract** _(AC2, integration)_

1. Temporarily add an import of src.api into a module under src/repository/
1. Run: cd backend && uv run lint-imports
1. Assert the process exit code is non-zero and the violation is named in the output
1. Revert the temporary import and assert the contract passes again

**`F225` — No API route module imports a repository module directly** _(AC3, integration)_

1. Run: grep -rnE 'from (backend\.)?src\.repository|import (backend\.)?src\.repository' backend/src/api/routes/
1. Assert the command exits with status 1 (no matches)
1. Assert the equivalent structural test in tests/architecture/ passes

**`F226` — The domain policy package has no dependency outside the standard library and types** _(AC4, integration)_

1. Parse the import statements of every module under backend/src/domain/
1. Assert no import references src.config, src.repository, src.service or src.api
1. Assert no third-party package is imported by any domain module
1. Assert the corresponding structural test passes

**`F227` — Dependency-cruiser reports zero frontend boundary violations** _(AC5, integration)_

1. Run the dependency-cruiser validation command in the frontend workspace
1. Assert the process exit code is 0
1. Assert the reported error count is 0
