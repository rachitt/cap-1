## Description

Brief section 7.1 rewards domain-specific substrate beyond the Harness defaults. This story adds the banking hooks that make NFR-01 and NFR-02 unbreakable at the tool-call boundary, plus banking skills, commands and agents. It sits in group A deliberately: the money-precision hook must be installed before any money code is generated, or it guards nothing.

## Acceptance Criteria

**AC1.** A `money-precision-check` hook rejects a write introducing `float(`, a `: float` annotation on a money field, or a `%f` format against backend source, and permits an equivalent `Decimal` implementation (NFR-01).

| Feature | Category | Verifies |
|---|---|---|
| `F228` | security | The money-precision hook blocks a write introducing float into a money path |

**AC2.** An `audit-immutability-check` hook rejects a write introducing an `UPDATE` or `DELETE` statement or an ORM mutation targeting the audit table, and permits an `append` call (NFR-02, DR-28).

| Feature | Category | Verifies |
|---|---|---|
| `F229` | security | The audit-immutability hook blocks writes that mutate the audit table |

**AC3.** A `pii-scrub` hook rejects a write that would log a password, bearer token or KYC document number, complementing the runtime redaction filter (NFR-03, DR-32).

| Feature | Category | Verifies |

## Verification Steps

**`F228` — The money-precision hook blocks a write introducing float into a money path** _(AC1, security)_

1. Invoke the hook with a candidate write containing 'balance: float = 0.0'
1. Assert the hook exits with a blocking status and emits a message naming the money precision rule
1. Invoke the hook with the equivalent 'balance: Decimal' write
1. Assert the hook permits the write

**`F229` — The audit-immutability hook blocks writes that mutate the audit table** _(AC2, security)_

1. Invoke the hook with a candidate write containing 'DELETE FROM audit_entries'
1. Assert the hook exits with a blocking status
1. Invoke the hook with a write containing an ORM update against the AuditEntry model and assert it is blocked
1. Invoke the hook with an audit append call and assert it is permitted

**`F230` — The pii-scrub hook blocks writes that log credentials or document numbers** _(AC3, security)_

1. Invoke the hook with a candidate write containing logger.info with a password variable interpolated
1. Assert the hook exits with a blocking status
1. Invoke the hook with a write logging a document_number field and assert it is blocked
1. Invoke the hook with a write logging only a correlation_id and assert it is permitted

**`F231` — At least two banking-specific skills exist beyond the Harness defaults** _(AC4, integration)_

1. List the directories under .claude/skills/ and identify those added for the banking domain
1. Assert at least 2 banking-specific skills are present
1. Assert each has a SKILL.md with a valid name and description front matter

**`F232` — At least two banking-specific commands exist beyond scaffold.md** _(AC4, integration)_

1. List the files under .claude/commands/
1. Assert the count is at least 3 including the pre-existing scaffold.md
1. Assert at least 2 files are banking-domain commands
1. Assert each command file carries a valid description front matter

**`F233` — At least two banking-specific agent definitions exist with valid front matter** _(AC5, integration)_

1. List the files under .claude/agents/ and identify those added for the banking domain
1. Assert at least 2 banking-specific agents are present beyond the seven Harness defaults
1. Assert each declares a name, a description and a tools list
1. Assert each agent file parses as valid front matter plus body
