## Description

All repositories share one engine, one session factory and one money column type. SQLAlchemy is configured against SQLite with a `Numeric(18, 2)` type decorator that returns `Decimal` on read rather than float, which is where NFR-01 is most easily lost. Alembic is initialised with an append-only migration policy per NFR-05.

## Acceptance Criteria

**AC1.** A `MoneyType` SQLAlchemy `TypeDecorator` over `Numeric(precision=18, scale=2)` round-trips `Decimal('1234.56')` through SQLite and returns a `Decimal`, never a `float`.

| Feature | Category | Verifies |
|---|---|---|
| `F018` | functional | Money values round-trip through SQLite as Decimal with full precision preserved |
| `F019` | functional | MoneyType preserves trailing-zero scale for whole-currency amounts |

**AC2.** A session factory yields a transactional scope where an exception raised inside the scope rolls back all writes, verified by inserting a row, raising, and asserting the row count is 0 afterwards.

| Feature | Category | Verifies |
|---|---|---|
| `F020` | functional | The session scope rolls back every write when an exception escapes the block |
| `F021` | functional | The session scope commits all writes when the block exits normally |

**AC3.** Alembic is configured and `uv run alembic upgrade head` creates every table in the BRD section 9 data model from a clean database file, exiting with status 0.

| Feature | Category | Verifies |
|---|---|---|
| `F022` | integration | Alembic upgrade head builds the full schema from an empty database |

**AC4.** SQLite money columns are declared `NUMERIC(18, 2)`; inspecting the `accounts` table schema shows the `balance` column type is NUMERIC and not REAL or FLOAT.

| Feature | Category | Verifies |
|---|---|---|
| `F023` | integration | No money column in the migrated schema is stored as REAL or FLOAT |

**AC5.** The repository layer imports only from `types` and `config`; a grep for `src.service` or `src.api` under `backend/src/repository/` returns zero matches (NFR-08).

| Feature | Category | Verifies |
|---|---|---|
| `F024` | integration | Repository layer contains no imports from Service or API layers |

## Verification Steps

**`F018` — Money values round-trip through SQLite as Decimal with full precision preserved** _(AC1, functional)_

1. Create an in-memory SQLite table with a MoneyType column
1. Insert Decimal('1234.56') and commit
1. Read the row back and assert the value is exactly Decimal('1234.56')
1. Assert isinstance(value, Decimal) is True and isinstance(value, float) is False

**`F019` — MoneyType preserves trailing-zero scale for whole-currency amounts** _(AC1, functional)_

1. Insert Decimal('100.00') through a MoneyType column and read it back
1. Assert the returned value equals Decimal('100.00')
1. Assert str(value) == '100.00' so the two-decimal scale survives persistence

**`F020` — The session scope rolls back every write when an exception escapes the block** _(AC2, functional)_

1. Open a session scope and insert one account row without committing explicitly
1. Raise a RuntimeError inside the scope and catch it outside
1. Open a new session and count rows in the accounts table
1. Assert the count is 0

**`F021` — The session scope commits all writes when the block exits normally** _(AC2, functional)_

1. Open a session scope, insert one account row, and exit the block without error
1. Open a new session and query for the inserted row
1. Assert exactly one row is returned

**`F022` — Alembic upgrade head builds the full schema from an empty database** _(AC3, integration)_

1. Delete any existing SQLite database file
1. Run: cd backend && uv run alembic upgrade head
1. Assert the process exit code is 0
1. Query sqlite_master and assert tables customers, kyc_records, accounts, transactions, transfers, beneficiaries, loan_applications, loan_state_transitions, audit_entries and notifications all exist

**`F023` — No money column in the migrated schema is stored as REAL or FLOAT** _(AC4, integration)_

1. Run alembic upgrade head against a clean database
1. Query PRAGMA table_info(accounts) and locate the balance column
1. Assert its declared type starts with 'NUMERIC'
1. Query sqlite_master for all CREATE TABLE statements and assert none contains 'REAL' or 'FLOAT'

**`F024` — Repository layer contains no imports from Service or API layers** _(AC5, integration)_

1. Run: grep -rnE 'from (backend\.)?src\.(service|api)|import (backend\.)?src\.(service|api)' backend/src/repository/
1. Assert the command exits with status 1 (no matches)
