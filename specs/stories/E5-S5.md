## Description

Completes AC-09 and the administrator-visible half of AC-10. Two admin-only read endpoints expose the append-only ledger over transactions and loan transitions, filterable by entity type, actor and date range, plus the dispatched notification log. Both are read-only: no write verb is routed against either resource.

## Acceptance Criteria

**AC1.** `GET /api/v1/admin/audit` returns 200 for an ADMIN token with entries covering both transactions and loan state transitions, each carrying timestamp, actor, action, entity type, entity reference and correlation ID (AC-09, DR-29).

| Feature | Category | Verifies |
|---|---|---|
| `F160` | functional | The admin audit endpoint returns entries for both transfers and loan transitions |

**AC2.** The audit endpoint supports filtering by `entity_type`, `actor_id` and a date range, returning only matching entries ordered most-recent-first.

| Feature | Category | Verifies |
|---|---|---|
| `F161` | functional | Audit filtering by entity_type and actor returns only matching entries |
| `F162` | functional | A date range excluding all entries returns 200 with an empty result |

**AC3.** A CUSTOMER token calling `GET /api/v1/admin/audit` or `GET /api/v1/admin/notifications` receives 403, and an unauthenticated call receives 401 (DR-33, edge cases E-14, E-15).

| Feature | Category | Verifies |
|---|---|---|
| `F163` | security | Customer and anonymous callers cannot read the admin audit ledger |
| `F164` | security | Customer and anonymous callers cannot read the admin notification log |

**AC4.** `GET /api/v1/admin/notifications` returns 200 for an ADMIN token listing dispatched notifications with channel, event type and status, including entries generated by transfers and by every loan transition (AC-10).

| Feature | Category | Verifies |
|---|---|---|
| `F165` | functional | The admin notification log lists transfer and loan notifications with channel and status |

**AC5.** No write verb is exposed against the audit resource: `POST`, `PUT`, `PATCH` and `DELETE` on `/api/v1/admin/audit` all return 405 (NFR-02, DR-28).

| Feature | Category | Verifies |
|---|---|---|
| `F166` | security | The audit endpoint exposes no write verb |

## Verification Steps

**`F160` — The admin audit endpoint returns entries for both transfers and loan transitions** _(AC1, functional)_

1. Execute one transfer and take one loan through a state transition
1. GET /api/v1/admin/audit as the seeded admin and assert status 200
1. Assert the result contains at least one entry with entity_type 'Transfer' and one with 'LoanApplication'
1. Assert every entry carries occurred_at, actor_id, action, entity_type, entity_id and correlation_id

**`F161` — Audit filtering by entity_type and actor returns only matching entries** _(AC2, functional)_

1. Generate audit entries across two entity types and two actors
1. GET /api/v1/admin/audit?entity_type=Transfer and assert every returned entry has entity_type 'Transfer'
1. GET /api/v1/admin/audit filtered by one actor_id and assert every entry matches that actor
1. Assert results are ordered with the most recent occurred_at first

**`F162` — A date range excluding all entries returns 200 with an empty result** _(AC2, functional)_

1. GET /api/v1/admin/audit with a from/to date range entirely in the past
1. Assert the response status is 200
1. Assert the returned entry array is empty rather than a 404

**`F163` — Customer and anonymous callers cannot read the admin audit ledger** _(AC3, security)_

1. GET /api/v1/admin/audit authenticated as a CUSTOMER and assert status 403
1. GET /api/v1/admin/audit with no Authorization header and assert status 401
1. Assert neither response body contains audit entries

**`F164` — Customer and anonymous callers cannot read the admin notification log** _(AC3, security)_

1. GET /api/v1/admin/notifications authenticated as a CUSTOMER and assert status 403
1. GET /api/v1/admin/notifications with no Authorization header and assert status 401

**`F165` — The admin notification log lists transfer and loan notifications with channel and status** _(AC4, functional)_

1. Execute a successful transfer and take a loan through one state transition
1. GET /api/v1/admin/notifications as admin and assert status 200
1. Assert at least one entry has event_type 'TRANSFER_COMPLETED' and one relates to a loan transition
1. Assert every entry carries channel, event_type and status fields

**`F166` — The audit endpoint exposes no write verb** _(AC5, security)_

1. Send POST, PUT, PATCH and DELETE to /api/v1/admin/audit as an authenticated admin
1. Assert every response status is 405 Method Not Allowed
1. Assert the audit_entries row count is unchanged after all four attempts
