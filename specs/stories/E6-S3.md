## Description

Delivers the browser half of AC-02 and AC-03. The dashboard lists owned accounts with balances and offers the open-account action; account detail shows the balance plus a paginated statement. Balances render from decimal strings via formatMoney with no client-side arithmetic.

## Acceptance Criteria

**AC1.** The dashboard lists every account returned by `GET /api/v1/accounts` with its balance formatted to two decimal places, and renders an empty state with an open-account call to action when the customer has none (AC-02).

| Feature | Category | Verifies |
|---|---|---|
| `F182` | ui | The dashboard renders each owned account with a two-decimal formatted balance |
| `F183` | ui | A customer with no accounts sees an empty state with an open-account action |

**AC2.** Triggering the open-account action calls `POST /api/v1/accounts` and renders the new account with a balance of `0.00` without a full page reload (AC-02).

| Feature | Category | Verifies |
|---|---|---|
| `F184` | ui | Opening an account adds it to the dashboard showing a 0.00 balance |

**AC3.** Account detail renders the paginated statement from `GET /api/v1/accounts/{id}/statements` most-recent-first, with working pagination controls that request the next page (AC-03, DR-13).

| Feature | Category | Verifies |
|---|---|---|
| `F185` | ui | The statement renders most-recent-first with each row showing direction and amount |
| `F186` | ui | Pagination controls request the next page of statements |

**AC4.** An account with no transactions renders an explicit empty statement state rather than an error or an infinite loading state (edge case E-20).

| Feature | Category | Verifies |
|---|---|---|
| `F187` | ui | An account with no transactions renders an empty statement state |

## Verification Steps

**`F182` — The dashboard renders each owned account with a two-decimal formatted balance** _(AC1, ui)_

1. Render the Dashboard with the accounts endpoint mocked to return two accounts with balances '1000.5' and '0'
1. Assert two account cards are rendered
1. Assert the displayed balances read '1,000.50' and '0.00'

**`F183` — A customer with no accounts sees an empty state with an open-account action** _(AC1, ui)_

1. Render the Dashboard with the accounts endpoint mocked to return an empty array
1. Assert an empty state message is rendered
1. Assert a visible control to open a savings account is present

**`F184` — Opening an account adds it to the dashboard showing a 0.00 balance** _(AC2, ui)_

1. Render the Dashboard and activate the open-account control with the endpoint mocked to return 201 and balance '0.00'
1. Assert POST /api/v1/accounts was called
1. Assert a new account card appears with the displayed balance '0.00'

**`F185` — The statement renders most-recent-first with each row showing direction and amount** _(AC3, ui)_

1. Render AccountDetail with the statements endpoint mocked to return 20 items and total 25
1. Assert 20 statement rows are rendered
1. Assert the first row corresponds to the newest transaction in the mocked payload
1. Assert each row displays its direction and a two-decimal formatted amount

**`F186` — Pagination controls request the next page of statements** _(AC3, ui)_

1. Render AccountDetail with total 25 and page size 20
1. Activate the next-page control
1. Assert the statements endpoint was called with page=2
1. Assert the rendered rows update to the second page payload

**`F187` — An account with no transactions renders an empty statement state** _(AC4, ui)_

1. Render AccountDetail with the statements endpoint mocked to return an empty items array and total 0
1. Assert an empty-state message is rendered
1. Assert no error message and no loading spinner remains visible
