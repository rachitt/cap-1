## Description

Delivers the four auth endpoints and, critically, the reusable FastAPI dependencies that enforce NFR-04 for every route added later. `require_principal` rejects missing or invalid bearer tokens with 401; `require_admin` rejects a CUSTOMER principal with 403. No route in the system is anonymous except /health, register and login.

## Acceptance Criteria

**AC1.** `POST /api/v1/auth/register` returns 201 with the new customer id and `status: "PENDING_KYC"`, and returns 409 when the email is already registered.

| Feature | Category | Verifies |
|---|---|---|
| `F051` | functional | POST /api/v1/auth/register returns 201 with a customer id and PENDING_KYC status |
| `F052` | functional | Registering a duplicate email returns 409 |

**AC2.** `POST /api/v1/auth/kyc` returns 200 with the verdict and activates the customer on a pass, returns 422 for a malformed document, and 409 when KYC was already verified.

| Feature | Category | Verifies |
|---|---|---|
| `F053` | functional | POST /api/v1/auth/kyc returns 200 and activates the customer on a passing verdict |
| `F054` | functional | Malformed KYC input returns 422 and a repeat submission returns 409 |

**AC3.** `POST /api/v1/auth/login` returns 200 with an `access_token` for an ACTIVE customer, 401 for wrong credentials, and 403 with a `PENDING_KYC` error code for an unactivated customer (AC-01, edge case E-09).

| Feature | Category | Verifies |
|---|---|---|
| `F055` | functional | Login returns 200 with a bearer access_token for an activated customer |
| `F056` | security | Login returns 401 for bad credentials and 403 for an unactivated customer, with distinguishable responses |

**AC4.** `GET /api/v1/auth/me` returns 200 with the current principal's id, email and role when a valid bearer token is supplied, and 401 when the Authorization header is missing, malformed or carries an expired token (edge case E-15).

| Feature | Category | Verifies |
|---|---|---|
| `F057` | functional | GET /api/v1/auth/me returns the authenticated principal for a valid token |
| `F058` | security | Missing, malformed and expired bearer tokens all return 401 |

**AC5.** The `require_admin` dependency returns 403 when a CUSTOMER-role token calls an admin-guarded route, and admin identities exist only via seeding — there is no route that creates an ADMIN customer (edge case E-14, OUT-11).

| Feature | Category | Verifies |
|---|---|---|
| `F059` | security | A CUSTOMER-role token calling an admin-guarded route receives 403 |
| `F060` | security | No public endpoint permits self-registration with the ADMIN role |

## Verification Steps

**`F051` — POST /api/v1/auth/register returns 201 with a customer id and PENDING_KYC status** _(AC1, functional)_

1. POST /api/v1/auth/register with a unique email, valid password, full_name and date_of_birth
1. Assert the response status is 201
1. Assert the JSON body contains a non-null 'id' and 'status' == 'PENDING_KYC'
1. Assert the response body contains no 'password' or 'password_hash' field

**`F052` — Registering a duplicate email returns 409** _(AC1, functional)_

1. POST /api/v1/auth/register with email 'dup@horizon.test' and assert 201
1. POST /api/v1/auth/register again with the same email
1. Assert the response status is 409

**`F053` — POST /api/v1/auth/kyc returns 200 and activates the customer on a passing verdict** _(AC2, functional)_

1. Register a customer, then POST /api/v1/auth/kyc with document_type='PASSPORT' and document_number='P1234567'
1. Assert the response status is 200 and the body status field is 'VERIFIED'
1. POST /api/v1/auth/login with that customer's credentials and assert status 200

**`F054` — Malformed KYC input returns 422 and a repeat submission returns 409** _(AC2, functional)_

1. POST /api/v1/auth/kyc with document_type='LIBRARY_CARD' and assert the response status is 422
1. Complete a valid KYC submission for a second customer and assert 200
1. POST /api/v1/auth/kyc again for that same customer and assert the response status is 409

**`F055` — Login returns 200 with a bearer access_token for an activated customer** _(AC3, functional)_

1. Register and complete KYC for a customer
1. POST /api/v1/auth/login with the correct email and password
1. Assert the response status is 200
1. Assert the body contains a non-empty 'access_token' and token_type == 'bearer'

**`F056` — Login returns 401 for bad credentials and 403 for an unactivated customer, with distinguishable responses** _(AC3, security)_

1. POST /api/v1/auth/login with a correct email but wrong password and assert status 401
1. Register a new customer without KYC and POST /api/v1/auth/login with correct credentials
1. Assert the response status is 403
1. Assert the 403 body carries an error code identifying PENDING_KYC

**`F057` — GET /api/v1/auth/me returns the authenticated principal for a valid token** _(AC4, functional)_

1. Obtain an access_token via login
1. GET /api/v1/auth/me with header Authorization: Bearer <token>
1. Assert the response status is 200
1. Assert the body id, email and role match the logged-in customer

**`F058` — Missing, malformed and expired bearer tokens all return 401** _(AC4, security)_

1. GET /api/v1/auth/me with no Authorization header and assert status 401
1. GET /api/v1/auth/me with header 'Authorization: Bearer not-a-jwt' and assert status 401
1. Mint a token with an exp in the past and GET /api/v1/auth/me with it
1. Assert the response status is 401

**`F059` — A CUSTOMER-role token calling an admin-guarded route receives 403** _(AC5, security)_

1. Log in as a seeded CUSTOMER and obtain a token
1. Call an admin-guarded route with that token
1. Assert the response status is 403 and not 401 or 200

**`F060` — No public endpoint permits self-registration with the ADMIN role** _(AC5, security)_

1. POST /api/v1/auth/register with an extra field role='ADMIN'
1. Assert the response is 201 or 422 but never creates an admin
1. Read the created customer row and assert role == 'CUSTOMER'
1. Run: grep -rn "Role.ADMIN" backend/src/api/routes/auth.py and assert no assignment of ADMIN occurs in a registration handler
