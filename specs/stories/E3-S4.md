## Description

Three routes completing AC-02 and AC-03 over HTTP. All are guarded by require_principal so an unauthenticated call is 401 and a cross-customer call is 403. Money is serialised as a JSON string to avoid IEEE-754 corruption in transit.

## Acceptance Criteria

**AC1.** `POST /api/v1/accounts` returns 201 with `balance: "0.00"` as a JSON string, and returns 401 without a bearer token (AC-02).

| Feature | Category | Verifies |
|---|---|---|
| `F080` | functional | POST /api/v1/accounts returns 201 with a zero balance rendered as the string 0.00 |
| `F081` | security | POST /api/v1/accounts without a bearer token returns 401 |

**AC2.** `GET /api/v1/accounts` returns 200 with only the caller's accounts and their balances as strings (AC-03).

| Feature | Category | Verifies |
|---|---|---|
| `F082` | functional | GET /api/v1/accounts returns 200 listing only the caller's own accounts |

**AC3.** `GET /api/v1/accounts/{id}/statements` returns 200 with a paginated body containing `items`, `page`, `page_size` and `total`, and returns 200 with an empty `items` array for an account with no transactions (edge case E-20).

| Feature | Category | Verifies |
|---|---|---|
| `F083` | functional | The statements endpoint returns a paginated envelope with items, page, page_size and total |
| `F084` | functional | An account with no transactions returns 200 with an empty items array rather than 404 |

**AC4.** Requesting statements for an account owned by another customer returns 403, not 404 and not 200 (edge case E-19).

| Feature | Category | Verifies |
|---|---|---|
| `F085` | security | Cross-customer statement access returns 403 |

## Verification Steps

**`F080` — POST /api/v1/accounts returns 201 with a zero balance rendered as the string 0.00** _(AC1, functional)_

1. Authenticate as a customer and POST /api/v1/accounts
1. Assert the response status is 201
1. Assert the raw response text contains '"balance":"0.00"' or '"balance": "0.00"'
1. Assert json.loads gives balance as a str instance, not a float

**`F081` — POST /api/v1/accounts without a bearer token returns 401** _(AC1, security)_

1. POST /api/v1/accounts with no Authorization header
1. Assert the response status is 401
1. Assert no account row was created in the database

**`F082` — GET /api/v1/accounts returns 200 listing only the caller's own accounts** _(AC2, functional)_

1. Create two accounts as customer A and one as customer B
1. GET /api/v1/accounts authenticated as A
1. Assert the response status is 200 and the array length is 2
1. Assert no returned account id belongs to customer B

**`F083` — The statements endpoint returns a paginated envelope with items, page, page_size and total** _(AC3, functional)_

1. Seed 25 transactions on an owned account
1. GET /api/v1/accounts/{id}/statements?page=1
1. Assert the response status is 200 and the body has keys items, page, page_size and total
1. Assert len(items) == 20 and total == 25

**`F084` — An account with no transactions returns 200 with an empty items array rather than 404** _(AC3, functional)_

1. Create a fresh account with no transactions
1. GET /api/v1/accounts/{id}/statements
1. Assert the response status is 200 and not 404
1. Assert items is an empty array and total is 0

**`F085` — Cross-customer statement access returns 403** _(AC4, security)_

1. Create an account as customer A and authenticate as customer B
1. GET /api/v1/accounts/{A_account_id}/statements as B
1. Assert the response status is exactly 403
1. Assert the response body contains no transaction data
