## Description

Delivers the browser half of AC-07. The customer applies for a personal loan and tracks it through the full state history. Because DR-24 imposes no eligibility criteria, the form collects principal, tenure and purpose and validates only structural well-formedness; it must not imply an eligibility decision is being made client-side.

## Acceptance Criteria

**AC1.** Submitting the loan application form calls `POST /api/v1/loans` and renders the new application with status `APPLIED` on a 201 response (AC-07).

| Feature | Category | Verifies |
|---|---|---|
| `F196` | ui | A submitted loan application renders with APPLIED status |
| `F197` | ui | The application form validates structural input only and asserts no eligibility outcome |

**AC2.** The screen renders the loan status timeline from `GET /api/v1/loans/{id}` showing every transition in chronological order with its reason and timestamp (AC-07, DR-26).

| Feature | Category | Verifies |
|---|---|---|
| `F198` | ui | The loan timeline renders every transition chronologically with reason and timestamp |

**AC3.** A rejected loan renders its rejection reason to the customer, and a disbursed loan indicates the crediting of the applicant's account (AC-08, DR-27).

| Feature | Category | Verifies |
|---|---|---|
| `F199` | ui | A rejected loan surfaces the administrator's recorded reason |
| `F200` | ui | A disbursed loan indicates the credited amount |

**AC4.** A customer with no loan applications sees an explicit empty state with a call to action rather than a blank panel.

| Feature | Category | Verifies |
|---|---|---|
| `F201` | ui | A customer with no loans sees an empty state with an apply action |

## Verification Steps

**`F196` — A submitted loan application renders with APPLIED status** _(AC1, ui)_

1. Render the Loans screen and submit principal '5000.00', tenure 24 and a purpose
1. Assert POST /api/v1/loans was called with those values
1. Assert the new application is rendered in the list with status APPLIED

**`F197` — The application form validates structural input only and asserts no eligibility outcome** _(AC1, ui)_

1. Enter principal '0' and attempt to submit, asserting a validation message and no API call
1. Enter principal '5000.001' and assert a validation message about decimal places
1. Assert no rendered text claims the customer is eligible or ineligible before the administrator decides

**`F198` — The loan timeline renders every transition chronologically with reason and timestamp** _(AC2, ui)_

1. Render the Loans screen with a loan mocked as having transitions to UNDER_REVIEW and APPROVED
1. Assert a timeline with 2 transition entries is rendered
1. Assert the entries appear in chronological order
1. Assert each entry displays its status, reason and timestamp

**`F199` — A rejected loan surfaces the administrator's recorded reason** _(AC3, ui)_

1. Render the Loans screen with a loan mocked as REJECTED carrying reason 'Insufficient documentation'
1. Assert the status REJECTED is rendered
1. Assert the reason text 'Insufficient documentation' is visible to the customer

**`F200` — A disbursed loan indicates the credited amount** _(AC3, ui)_

1. Render the Loans screen with a loan mocked as DISBURSED with principal '5000.00'
1. Assert the status DISBURSED is rendered
1. Assert the formatted principal '5,000.00' is displayed as the disbursed amount

**`F201` — A customer with no loans sees an empty state with an apply action** _(AC4, ui)_

1. Render the Loans screen with the loans endpoint mocked to return an empty array
1. Assert an empty-state message is rendered
1. Assert a visible control to start a loan application is present
