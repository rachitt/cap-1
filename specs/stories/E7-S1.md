## Description

Delivers the browser half of AC-08. The administrator works a filterable queue and takes one of four actions. The mandatory-reason rule from DR-25 is enforced in the UI as well as the API, so the approve and reject controls cannot be submitted without a reason.

## Acceptance Criteria

**AC1.** The queue renders loans from `GET /api/v1/admin/loans` with applicant, principal, tenure and status, and the status filter re-queries the endpoint with the selected status (AC-08).

| Feature | Category | Verifies |
|---|---|---|
| `F202` | ui | The loan queue renders applications with their key fields |
| `F203` | ui | Selecting a status filter re-queries the admin loans endpoint |

**AC2.** The approve and reject controls cannot be submitted with an empty reason: the submit action stays disabled or produces a validation message, and no API call is made (DR-25, AC-08).

| Feature | Category | Verifies |
|---|---|---|
| `F204` | ui | Approving with an empty reason is blocked before any API call |
| `F205` | ui | Rejecting with a whitespace-only reason is blocked before any API call |

**AC3.** Submitting an approve or reject with a non-empty reason calls the corresponding endpoint with that reason and updates the row's status in place on a 200 response (AC-08).

| Feature | Category | Verifies |
|---|---|---|
| `F206` | ui | A valid approval calls the approve endpoint and updates the row status |
| `F207` | ui | A valid rejection calls the reject endpoint and updates the row status |

**AC4.** The review and disburse actions are offered only for loans in a state where they are legal, and a 409 response renders an explicit illegal-transition message rather than a generic failure (edge cases E-11, E-22).

| Feature | Category | Verifies |
|---|---|---|
| `F208` | ui | Actions are offered only where the transition is legal for the row's status |
| `F209` | ui | A 409 response renders an explicit illegal-transition message |

## Verification Steps

**`F202` — The loan queue renders applications with their key fields** _(AC1, ui)_

1. Render the LoanQueue with the admin loans endpoint mocked to return three applications
1. Assert three queue rows are rendered
1. Assert each row displays applicant, formatted principal, tenure and status

**`F203` — Selecting a status filter re-queries the admin loans endpoint** _(AC1, ui)_

1. Render the LoanQueue and select the UNDER_REVIEW status filter
1. Assert GET /api/v1/admin/loans was called with status=UNDER_REVIEW
1. Assert the rendered rows update to the filtered payload

**`F204` — Approving with an empty reason is blocked before any API call** _(AC2, ui)_

1. Open the approve action on an UNDER_REVIEW loan and leave the reason field empty
1. Attempt to submit the decision
1. Assert no POST to the approve endpoint was made
1. Assert a validation message or disabled submit control prevents the action

**`F205` — Rejecting with a whitespace-only reason is blocked before any API call** _(AC2, ui)_

1. Open the reject action and enter only spaces in the reason field
1. Attempt to submit the decision
1. Assert no POST to the reject endpoint was made
1. Assert a validation message is rendered

**`F206` — A valid approval calls the approve endpoint and updates the row status** _(AC3, ui)_

1. Open the approve action on an UNDER_REVIEW loan and enter reason 'Documents verified'
1. Submit with the endpoint mocked to return 200 and status APPROVED
1. Assert POST /api/v1/admin/loans/{id}/approve was called with that reason
1. Assert the row status updates to APPROVED without a page reload

**`F207` — A valid rejection calls the reject endpoint and updates the row status** _(AC3, ui)_

1. Open the reject action and enter reason 'Insufficient documentation'
1. Submit with the endpoint mocked to return 200 and status REJECTED
1. Assert POST /api/v1/admin/loans/{id}/reject was called with that reason
1. Assert the row status updates to REJECTED

**`F208` — Actions are offered only where the transition is legal for the row's status** _(AC4, ui)_

1. Render the queue with loans in APPLIED, UNDER_REVIEW and APPROVED states
1. Assert the APPLIED row offers review but not approve or disburse
1. Assert the UNDER_REVIEW row offers approve and reject but not disburse
1. Assert the APPROVED row offers disburse

**`F209` — A 409 response renders an explicit illegal-transition message** _(AC4, ui)_

1. Trigger a decision action with the endpoint mocked to return 409
1. Assert an error message referring to an invalid state transition is rendered
1. Assert the row status is not optimistically changed
