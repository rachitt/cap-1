## Description

HTTP surface for AC-07 and AC-08. Customer routes expose application and the status timeline; admin routes expose the pending queue and the four decision actions, each guarded by require_admin so a customer token receives 403. Illegal transitions surface as 409 and a missing reason as 422.

## Acceptance Criteria

**AC1.** `POST /api/v1/loans` returns 201 with `status: "APPLIED"`, and `GET /api/v1/loans/{id}` returns 200 including the full ordered status timeline (AC-07).

| Feature | Category | Verifies |
|---|---|---|
| `F149` | functional | POST /api/v1/loans returns 201 with APPLIED status and a string principal |
| `F150` | functional | GET /api/v1/loans/{id} returns the loan with its full ordered transition timeline |
| `F151` | security | Requesting another customer's loan returns 403 |

**AC2.** `GET /api/v1/admin/loans` returns 200 with the pending queue filterable by status for an ADMIN token, and returns 403 for a CUSTOMER token (AC-08, edge case E-14).

| Feature | Category | Verifies |
|---|---|---|
| `F152` | functional | The admin loan queue returns 200 and supports status filtering |
| `F153` | security | A customer token calling the admin loan queue receives 403 |

**AC3.** `POST /api/v1/admin/loans/{id}/approve` and `/reject` return 200 with the new status when a non-empty reason is supplied, and return 422 when the reason is missing or empty (AC-08, edge case E-13).

| Feature | Category | Verifies |
|---|---|---|
| `F154` | functional | Approve and reject return 200 with the new status when a reason is supplied |
| `F155` | functional | Approve or reject without a reason returns 422 and does not change the loan status |

**AC4.** `POST /api/v1/admin/loans/{id}/review` moves APPLIED → UNDER_REVIEW returning 200, and any illegal transition such as approving an APPLIED loan returns 409 (AC-07, edge cases E-11, E-12).

| Feature | Category | Verifies |
|---|---|---|
| `F156` | functional | The review action moves an APPLIED loan to UNDER_REVIEW with 200 |
| `F157` | functional | An illegal loan transition returns 409 |

**AC5.** `POST /api/v1/admin/loans/{id}/disburse` returns 200 moving APPROVED → DISBURSED and credits the applicant's account, and returns 409 when the loan is not APPROVED (DR-27).

| Feature | Category | Verifies |
|---|---|---|
| `F158` | functional | Disbursing an approved loan returns 200 and credits the applicant's account |
| `F159` | functional | Disbursing a loan that is not APPROVED returns 409 |

## Verification Steps

**`F149` — POST /api/v1/loans returns 201 with APPLIED status and a string principal** _(AC1, functional)_

1. Authenticate as a customer and POST /api/v1/loans with principal '5000.00' and tenure_months 24
1. Assert the response status is 201
1. Assert the body status == 'APPLIED' and id is non-null
1. Assert the principal field is the JSON string '5000.00'

**`F150` — GET /api/v1/loans/{id} returns the loan with its full ordered transition timeline** _(AC1, functional)_

1. Take a loan through APPLIED, UNDER_REVIEW and APPROVED
1. GET /api/v1/loans/{id} as the owning customer and assert status 200
1. Assert the body contains a timeline array with 2 transition entries in chronological order
1. Assert each entry carries to_status, reason and a timestamp

**`F151` — Requesting another customer's loan returns 403** _(AC1, security)_

1. Create a loan as customer A
1. GET /api/v1/loans/{id} authenticated as customer B
1. Assert the response status is 403
1. Assert the body contains no loan data

**`F152` — The admin loan queue returns 200 and supports status filtering** _(AC2, functional)_

1. Seed loans in APPLIED and UNDER_REVIEW states and authenticate as the seeded admin
1. GET /api/v1/admin/loans?status=APPLIED and assert status 200
1. Assert every returned loan has status APPLIED
1. GET /api/v1/admin/loans with no filter and assert loans in both states are returned

**`F153` — A customer token calling the admin loan queue receives 403** _(AC2, security)_

1. Authenticate as a CUSTOMER and GET /api/v1/admin/loans
1. Assert the response status is 403
1. Assert the response body contains no loan queue data

**`F154` — Approve and reject return 200 with the new status when a reason is supplied** _(AC3, functional)_

1. Move a loan to UNDER_REVIEW as admin, then POST /api/v1/admin/loans/{id}/approve with reason 'Verified documents'
1. Assert the response status is 200 and the body status == 'APPROVED'
1. On a second UNDER_REVIEW loan POST /reject with reason 'Insufficient documentation'
1. Assert the response status is 200 and the body status == 'REJECTED'

**`F155` — Approve or reject without a reason returns 422 and does not change the loan status** _(AC3, functional)_

1. Move a loan to UNDER_REVIEW, then POST /approve with an empty reason and assert status 422
1. POST /approve with the reason field omitted entirely and assert status 422
1. GET the loan and assert its status is still UNDER_REVIEW

**`F156` — The review action moves an APPLIED loan to UNDER_REVIEW with 200** _(AC4, functional)_

1. Create an APPLIED loan and POST /api/v1/admin/loans/{id}/review as admin
1. Assert the response status is 200
1. Assert the body status == 'UNDER_REVIEW'

**`F157` — An illegal loan transition returns 409** _(AC4, functional)_

1. Create an APPLIED loan and POST /api/v1/admin/loans/{id}/approve with a valid reason
1. Assert the response status is 409
1. Take another loan to REJECTED and POST /approve on it, asserting status 409
1. Assert both loans retain their prior status

**`F158` — Disbursing an approved loan returns 200 and credits the applicant's account** _(AC5, functional)_

1. Take a loan of principal '5000.00' to APPROVED for a customer whose account holds 100.00
1. POST /api/v1/admin/loans/{id}/disburse as admin and assert status 200
1. Assert the body status == 'DISBURSED'
1. GET /api/v1/accounts as the customer and assert the balance is the string '5100.00'

**`F159` — Disbursing a loan that is not APPROVED returns 409** _(AC5, functional)_

1. Create a loan in APPLIED status and POST /api/v1/admin/loans/{id}/disburse as admin
1. Assert the response status is 409
1. Assert the loan status is still APPLIED and no account was credited
