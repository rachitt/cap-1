## Description

Everything the customer screens share. TypeScript types are generated from the FastAPI OpenAPI schema so backend and frontend types cannot drift, which is the mitigation recorded against Option A in the BRD. Design tokens encode the Horizon Bank identity, and a money formatting helper enforces DR-04 by formatting decimal strings without arithmetic.

## Acceptance Criteria

**AC1.** TypeScript API types are generated from the backend OpenAPI schema by a repeatable command, and the generated file is not hand-edited; re-running generation against an unchanged backend produces no diff.

| Feature | Category | Verifies |
|---|---|---|
| `F167` | integration | API types are generated from the OpenAPI schema and regeneration is idempotent |

**AC2.** A design token module defines the Horizon Bank palette, type scale and spacing scale as named tokens, and no screen component contains a raw hex colour literal.

| Feature | Category | Verifies |
|---|---|---|
| `F168` | ui | Design tokens are centralised and screens contain no raw hex colour literals |
| `F169` | ui | Money text meets WCAG AA contrast against its background in the token palette |

**AC3.** `formatMoney` renders a decimal string such as `'1234.5'` as `'1,234.50'` and performs no arithmetic; the frontend contains no `parseFloat` or `Number()` call applied to a money field (DR-04, NFR-01).

| Feature | Category | Verifies |
|---|---|---|
| `F170` | functional | formatMoney renders decimal strings with exactly two decimal places |
| `F171` | security | No money value is coerced to a JavaScript number anywhere in the frontend |

**AC4.** The auth layer stores the bearer token, attaches it as an `Authorization` header on every API call, and redirects to the login screen on a 401 response.

| Feature | Category | Verifies |
|---|---|---|
| `F172` | functional | The API client attaches the bearer token to authenticated requests |
| `F173` | functional | A 401 response clears the session and redirects to the login screen |

## Verification Steps

**`F167` — API types are generated from the OpenAPI schema and regeneration is idempotent** _(AC1, integration)_

1. Start the backend and run the frontend type generation command
1. Assert the command exits with status 0 and writes a generated types file
1. Run the generation command a second time
1. Assert git reports no diff on the generated file

**`F168` — Design tokens are centralised and screens contain no raw hex colour literals** _(AC2, ui)_

1. Assert the design token module exports named colour, type scale and spacing tokens
1. Run: grep -rnE '#[0-9a-fA-F]{3,8}' frontend/src --include=*.tsx
1. Assert the command returns no matches outside the design token module

**`F169` — Money text meets WCAG AA contrast against its background in the token palette** _(AC2, ui)_

1. Compute the contrast ratio between the money text token and the surface token it renders on
1. Assert the ratio is at least 4.5:1
1. Repeat for the error state token used by the insufficient-funds message and assert at least 4.5:1

**`F170` — formatMoney renders decimal strings with exactly two decimal places** _(AC3, functional)_

1. Call formatMoney('1234.5') and assert the result is '1,234.50'
1. Call formatMoney('0') and assert the result is '0.00'
1. Call formatMoney('999999.99') and assert the result is '999,999.99'

**`F171` — No money value is coerced to a JavaScript number anywhere in the frontend** _(AC3, security)_

1. Run: grep -rnE 'parseFloat|Number\(' frontend/src --include=*.ts --include=*.tsx
1. Assert no match is applied to a balance, amount or principal field
1. Assert formatMoney accepts a string parameter and never returns a number type

**`F172` — The API client attaches the bearer token to authenticated requests** _(AC4, functional)_

1. Set a token via the auth store and issue an API call through the client
1. Assert the outgoing request carries header Authorization: Bearer <token>
1. Clear the token and issue the call again
1. Assert no Authorization header is attached

**`F173` — A 401 response clears the session and redirects to the login screen** _(AC4, functional)_

1. Mock an API call returning 401
1. Invoke the call through the shared client
1. Assert the stored token is cleared
1. Assert the router navigates to the login route
