## Description

A Spec-Is-Truth cleanup. CLAUDE.md currently restates AC-01..AC-10 and NFR-01..NFR-08 inline, which creates a second source of truth that will drift from the specs. Once specs/app_spec.md exists as the authoritative statement, CLAUDE.md must reference it rather than restate it. The invariant table in CLAUDE.md is replaced by a pointer.

## Acceptance Criteria

**AC1.** `specs/app_spec.md` exists and states all ten acceptance criteria `AC-01`..`AC-10` and all eight non-functional requirements `NFR-01`..`NFR-08` in full, as the single authoritative source.

| Feature | Category | Verifies |
|---|---|---|
| `F258` | integration | specs/app_spec.md states all ten ACs and all eight NFRs |

**AC2.** `CLAUDE.md` no longer restates the AC and NFR text inline; it references `specs/app_spec.md` as authoritative, eliminating the duplicate source of truth.

| Feature | Category | Verifies |
|---|---|---|
| `F259` | integration | CLAUDE.md references app_spec.md instead of restating the requirement text |
| `F260` | integration | No requirement identifier is defined in two places with differing text |

**AC3.** Each acceptance criterion in `specs/app_spec.md` is traceable to at least one story in `specs/stories/` and at least one feature in `specs/features.json`.

| Feature | Category | Verifies |
|---|---|---|
| `F261` | integration | Every acceptance criterion traces to a story and a feature |

**AC4.** `specs/app_spec.md` asserts no requirement absent from the source brief: it contains no transfer cap, no loan eligibility threshold and no registration age criterion (DR-07, DR-19, DR-24).

| Feature | Category | Verifies |
|---|---|---|
| `F262` | integration | The authoritative spec contains no invented business rule |

## Verification Steps

**`F258` — specs/app_spec.md states all ten ACs and all eight NFRs** _(AC1, integration)_

1. Assert specs/app_spec.md exists
1. Assert it contains an identifier for each of AC-01 through AC-10
1. Assert it contains an identifier for each of NFR-01 through NFR-08
1. Assert each identifier is accompanied by a full requirement statement rather than a bare reference

**`F259` — CLAUDE.md references app_spec.md instead of restating the requirement text** _(AC2, integration)_

1. Read CLAUDE.md and assert it contains a reference to specs/app_spec.md as the authoritative requirement source
1. Assert CLAUDE.md no longer contains the full inline NFR-01 through NFR-08 statement table
1. Assert the Spec-Is-Truth rule remains stated in CLAUDE.md

**`F260` — No requirement identifier is defined in two places with differing text** _(AC2, integration)_

1. Extract every AC-NN and NFR-NN statement from specs/app_spec.md
1. Extract any AC-NN or NFR-NN statement remaining in CLAUDE.md
1. Assert no identifier carries a substantive requirement statement in both files
1. Assert the two documents do not contradict each other

**`F261` — Every acceptance criterion traces to a story and a feature** _(AC3, integration)_

1. Parse the AC identifiers from specs/app_spec.md
1. Grep specs/stories/ for each identifier and assert every AC appears in at least one story file
1. Parse specs/features.json and assert every AC identifier appears in at least one feature description or step
1. Assert no AC identifier is unreferenced

**`F262` — The authoritative spec contains no invented business rule** _(AC4, integration)_

1. Run: grep -niE 'daily cap|transfer cap|velocity|minimum balance|eligibility threshold|minimum age' specs/app_spec.md
1. Assert the command returns no match asserting such a rule as a requirement
1. Assert any mention of these appears only as an explicit statement that no such rule exists
1. Assert every requirement in the file cites an AC-NN or NFR-NN identifier
