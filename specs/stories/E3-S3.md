## Description

Orchestrates AC-02 and AC-03. Opening an account writes the account and an audit entry in one transaction. Balance and statement reads verify the calling principal owns the account before returning anything, which is where E-19 cross-customer access is stopped. This is the first consumer of the audit module.

## Acceptance Criteria

**AC1.** `open_account(principal)` creates a SAVINGS account at `Decimal('0.00')` and appends an audit entry with `action='ACCOUNT_OPENED'` and `entity_type='Account'` in the same transaction (AC-02, AC-09).

| Feature | Category | Verifies |
|---|---|---|
| `F075` | functional | Opening an account creates a zero-balance savings account and one matching audit entry |

**AC2.** `list_accounts(principal)` returns only accounts owned by that principal; a customer with two accounts and another customer with one sees exactly their own two.

| Feature | Category | Verifies |
|---|---|---|
| `F076` | security | Account listing is scoped to the calling principal only |

**AC3.** `get_statements(principal, account_id)` raises an ownership error when the account belongs to another customer, so the API returns 403 (edge case E-19).

| Feature | Category | Verifies |
|---|---|---|
| `F077` | security | Requesting another customer's statements raises an ownership error |

**AC4.** Balances are returned as `Decimal` through the service boundary and serialised as strings; no service method returns or accepts a `float` for a money value (NFR-01).

| Feature | Category | Verifies |
|---|---|---|
| `F078` | functional | The account service returns Decimal balances and contains no float usage |

**AC5.** `get_statements` returns pages of the configured size (default 20) ordered most-recent-first, honouring `statement_page_size` from the Config layer rather than a hard-coded literal (assumption A-06).

| Feature | Category | Verifies |
|---|---|---|
| `F079` | functional | Statement page size is read from configuration and applied to service results |

## Verification Steps

**`F075` — Opening an account creates a zero-balance savings account and one matching audit entry** _(AC1, functional)_

1. Call open_account for an authenticated customer principal
1. Assert the returned account balance == Decimal('0.00')
1. Query audit_entries for entity_type='Account' and entity_id equal to the new account id
1. Assert exactly one entry exists with action == 'ACCOUNT_OPENED' and actor_id equal to the customer id

**`F076` — Account listing is scoped to the calling principal only** _(AC2, security)_

1. Create customer A with two accounts and customer B with one account
1. Call list_accounts for principal A
1. Assert exactly 2 accounts are returned and every id belongs to A
1. Assert customer B's account id does not appear in the result

**`F077` — Requesting another customer's statements raises an ownership error** _(AC3, security)_

1. Create customer A with an account and customer B
1. Call get_statements with principal B and customer A's account_id inside pytest.raises(OwnershipError)
1. Assert the error is raised
1. Assert no statement rows are returned to B

**`F078` — The account service returns Decimal balances and contains no float usage** _(AC4, functional)_

1. Call list_accounts and inspect the balance on each returned account
1. Assert isinstance(balance, Decimal) for every account
1. Run: grep -nE 'float\(|:\s*float' backend/src/service/account_service.py
1. Assert the command exits with status 1

**`F079` — Statement page size is read from configuration and applied to service results** _(AC5, functional)_

1. Record 30 transactions on an owned account
1. Call get_statements with no explicit page size and assert 20 items are returned
1. Override statement_page_size to 5 in configuration and repeat the call
1. Assert exactly 5 items are returned, proving the value is configuration-driven
