## Description

NFR-02 enforced at three independent levels so a single mistake cannot defeat it: the repository exposes append and read methods only with no update or delete, SQLite triggers raise on UPDATE and DELETE against audit_entries, and a write-time hook rejects source introducing such statements. Callers pass a generic tuple, so the module depends on nothing above Repository.

## Acceptance Criteria

**AC1.** `append(actor_id, actor_role, action, entity_type, entity_id, correlation_id, metadata)` inserts one row with a server-assigned `occurred_at` and returns it; the repository class exposes no method whose name contains `update` or `delete`.

| Feature | Category | Verifies |
|---|---|---|
| `F061` | functional | audit_repository.append persists one entry with a server-assigned occurred_at timestamp |
| `F062` | security | The audit repository public surface contains no update or delete method |

**AC2.** SQLite triggers reject mutation: a raw `UPDATE audit_entries SET action='x'` and a raw `DELETE FROM audit_entries` each raise a database error, and the row count and original content are unchanged afterwards (edge case E-17).

| Feature | Category | Verifies |
|---|---|---|
| `F063` | security | A raw UPDATE against audit_entries is rejected by a database trigger |
| `F064` | security | A raw DELETE against audit_entries is rejected by a database trigger |

**AC3.** Read methods support filtering by `entity_type`, `actor_id` and an `occurred_at` date range, returning results ordered most-recent-first, backing the AC-09 admin viewer.

| Feature | Category | Verifies |
|---|---|---|
| `F065` | functional | Audit queries filter by entity_type and return most-recent-first ordering |
| `F066` | functional | Audit queries filter by actor_id and by an occurred_at date range |

**AC4.** An audit write failing inside an enclosing transaction rolls the whole transaction back, so no business state is committed without its audit trail (edge case E-16).

| Feature | Category | Verifies |
|---|---|---|
| `F067` | integration | A failed audit append rolls back the enclosing business transaction |

## Verification Steps

**`F061` — audit_repository.append persists one entry with a server-assigned occurred_at timestamp** _(AC1, functional)_

1. Call append with actor_id, actor_role='CUSTOMER', action='TRANSFER_COMPLETED', entity_type='Transfer', entity_id and a correlation_id
1. Assert the returned row has a non-null id and a non-null occurred_at
1. Query audit_entries and assert exactly one row exists with action == 'TRANSFER_COMPLETED'

**`F062` — The audit repository public surface contains no update or delete method** _(AC1, security)_

1. Introspect the AuditRepository class with dir()
1. Filter to public callables not starting with an underscore
1. Assert no name contains 'update', 'delete', 'remove' or 'purge'
1. Run: grep -niE 'def .*(update|delete)' backend/src/repository/audit_repository.py and assert no matches

**`F063` — A raw UPDATE against audit_entries is rejected by a database trigger** _(AC2, security)_

1. Append one audit entry and record its action value
1. Execute raw SQL: UPDATE audit_entries SET action='tampered' inside pytest.raises for a database error
1. Assert the error is raised
1. Re-read the row and assert its action still holds the original value

**`F064` — A raw DELETE against audit_entries is rejected by a database trigger** _(AC2, security)_

1. Append two audit entries and assert the row count is 2
1. Execute raw SQL: DELETE FROM audit_entries inside pytest.raises for a database error
1. Assert the error is raised
1. Re-count audit_entries and assert the count is still 2

**`F065` — Audit queries filter by entity_type and return most-recent-first ordering** _(AC3, functional)_

1. Append three entries with entity_type values 'Transfer', 'LoanApplication' and 'Transfer'
1. Query with entity_type='Transfer' and assert exactly 2 rows are returned
1. Assert the returned rows are ordered with the newest occurred_at first

**`F066` — Audit queries filter by actor_id and by an occurred_at date range** _(AC3, functional)_

1. Append entries for two distinct actor_id values
1. Query filtered by the first actor_id and assert only that actor's entries are returned
1. Query with a date range that excludes all entries and assert an empty list is returned

**`F067` — A failed audit append rolls back the enclosing business transaction** _(AC4, integration)_

1. Open a transaction, write a business row, then force the audit append to raise
1. Allow the exception to propagate out of the transaction scope
1. Open a new session and assert the business row was not committed
1. Assert the audit_entries table contains no partial entry for the operation
