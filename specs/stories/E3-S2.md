## Description

Persistence for accounts and the double-entry transaction rows that back statements. The account repository provides a locking read used by the transfer service to serialise concurrent debits. The transaction repository supports keyset or offset pagination ordered most-recent-first per assumption A-06.

## Acceptance Criteria

**AC1.** `create_account` persists a SAVINGS account with `balance = Decimal('0.00')`, a unique generated `account_number` and `status = ACTIVE` (AC-02).

| Feature | Category | Verifies |
|---|---|---|
| `F068` | functional | A created savings account starts at exactly Decimal 0.00 with ACTIVE status |
| `F069` | functional | Generated account numbers are unique across accounts |

**AC2.** `get_for_update(account_id)` re-reads the account inside the current transaction and is used to serialise concurrent balance changes; a test asserts the value it returns reflects a debit committed by a prior transaction.

| Feature | Category | Verifies |
|---|---|---|
| `F070` | functional | get_for_update re-reads the current committed balance inside the transaction |

**AC3.** `record_transaction` writes a row carrying `direction`, `amount`, `balance_after` and a shared `transfer_id`, so one transfer produces exactly two rows — one DEBIT and one CREDIT — that share that `transfer_id`.

| Feature | Category | Verifies |
|---|---|---|
| `F071` | functional | A single transfer id yields exactly one DEBIT and one CREDIT transaction row |
| `F072` | functional | Each transaction row stores the resulting balance_after as a Decimal |

**AC4.** `list_statements(account_id, page, page_size)` returns rows ordered most-recent-first with a total count, and an account with zero transactions returns an empty page rather than raising (edge case E-20).

| Feature | Category | Verifies |
|---|---|---|
| `F073` | functional | Statement listing paginates most-recent-first with a correct total count |
| `F074` | functional | An account with no transactions returns an empty page rather than raising |

## Verification Steps

**`F068` — A created savings account starts at exactly Decimal 0.00 with ACTIVE status** _(AC1, functional)_

1. Call create_account for an existing customer_id
1. Assert the returned account balance == Decimal('0.00') and its type is SAVINGS
1. Assert status == AccountStatus.ACTIVE and account_number is a non-empty string
1. Re-read the row in a new session and assert the balance is still Decimal('0.00')

**`F069` — Generated account numbers are unique across accounts** _(AC1, functional)_

1. Create three accounts for the same customer
1. Collect the three account_number values
1. Assert all three are distinct
1. Attempt to insert a duplicate account_number directly and assert an integrity error is raised

**`F070` — get_for_update re-reads the current committed balance inside the transaction** _(AC2, functional)_

1. Create an account and set its balance to Decimal('100.00')
1. In transaction one, debit 40.00 and commit
1. In a new transaction, call get_for_update on the same account id
1. Assert the returned balance is Decimal('60.00')

**`F071` — A single transfer id yields exactly one DEBIT and one CREDIT transaction row** _(AC3, functional)_

1. Record a DEBIT row and a CREDIT row sharing transfer_id T1
1. Query transactions filtered by transfer_id == T1
1. Assert exactly 2 rows are returned
1. Assert one row has direction DEBIT and the other CREDIT, and their amounts are equal

**`F072` — Each transaction row stores the resulting balance_after as a Decimal** _(AC3, functional)_

1. Record a DEBIT of 25.00 against an account whose balance becomes 75.00
1. Read the transaction row back
1. Assert balance_after == Decimal('75.00') and isinstance(balance_after, Decimal)

**`F073` — Statement listing paginates most-recent-first with a correct total count** _(AC4, functional)_

1. Record 25 transactions against one account with increasing created_at values
1. Call list_statements with page=1 and page_size=20
1. Assert 20 items are returned, the total count is 25, and the first item is the newest
1. Call with page=2 and assert exactly 5 items are returned

**`F074` — An account with no transactions returns an empty page rather than raising** _(AC4, functional)_

1. Create an account and record no transactions
1. Call list_statements with page=1
1. Assert the returned item list is empty and total is 0
1. Assert no exception is raised
